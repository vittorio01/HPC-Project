# HPC Project repository 
This repository will be used for the source code of two parallelized [Bat algorithm](https://www.researchgate.net/publication/45913690_A_New_Metaheuristic_Bat-Inspired_Algorithm) designed by Xin-She Yang. 
In particular there are three versions available: 
- `bat_algorithm_cpu`, the single process version of the algorithm used as reference for the parallel appliations. 
- `bat_algorithm_MPI`, the MPI multi-process version of the algorithm. 
- `bat_algorithm_hybrid`, the multi-thread version parallelized both with MPI and openMP.
  
The repository includes also three libraries:
- [`data.h`](lib/include/data.h), which implements an interface for dynamic data structures like Vector and Matrix types and their relative functions.
- [`tools.h`](lib/include/tools.h), which implements useful functions and data types for running the algorithms.
- [`benchmark.h`](lib/include/benchmark.h), which contains the fitness functions and the benchmark utilities.  

## Environment setup
The repository contains:
- `bat_algorithm_*` folders, which contains the implementation of the algorithms packed in a dedicated structure:
  * `main.c`, the actual algorithm source code plus the `main` function.
  * `include` folder, which contains eventual `.h` headers local to the implementation.
  * `src` folder, which contains eventual `.c` sources local to the implementation.
- `libs` filder, which contains the implementation of the common libraries shared between all the algorithms:
  * `include`, the folder that contains the `.h` headers of the libraries.
  * `src`, the folder that contains the `.c` sources of the libraries.
  * `lib,mk`, the makefile responsible for compiling the libraries. 
- `library_test`, that contains the code used for testing the common libraries. 
- `makefile`, a makefile useful for the compilation and the launch of the algorithms. 
- `flake.lock` and `flake.nix`, which defines the develop environmnent for NixOS.
  
### Requirements
To compile the source code are necessary the follow requirements: 
* `gcc` >= 12.3.0
* `GSL` >= 2.7
* `gnumake` >= 4.4.1
* `openMPI` >= 4.1.5
* `openMP` >= 19.0.0

### Compiling and launching the code 
The [`makefile`](makefile) contains the directive for an automatic compilation of the common libraries and the algorithms. The variable `PRG` should be modified in order to choose the version that the user wants to compile. For example:
```
make compile PRG=bat_algorithm_cpu
```
  
Theere are also directives for launching the compiled binary code in local or in a PBS cluster:
```
make run PRG=bat_algorithm_cpu       <- shedules the run.sh script generated by the compile directive to the cluster
make run-local PRC=bat_algorithm_cpu <- launch the bynary in the local machine
```

The compilation creates the `build` folder with the following structure: 
- `lib`, that cntains the headers, and the compiled common libraries in their respective subfolders. 
- `out`, that contains the binary file of the choosed algorithm.
- `log`, a folder used for storing the log files when launching the algorithm in the cluster.
- `run.sh`, the PBS script automatically generated for launching the algorithm in the cluster.

>[!WARNING]
>For PBS clusters the compilation is done in the login node Therefore remember to include the necessary module for MPI and GLS
```
module load OpenMPI/4.1.5-GCC-12.3.0
module load GSL/2.7-GCC-12.3.0
```

More options can be specified to the makefile: 
| Variable | Options |  Default | Description |
|------|---------|---------|-------------|
|`PRG`| `bat_alhorithm_cpu`/`bat_algorithm_MPI`/`bat_algorithm_hybrid` | | the name of the folder that contains the specific bat algorithm source to compile |
|`PROCESSES`| Integer | 1 | number of MPI processes to spawn when running the algorithms |
| `BATS`| Integer | 1000 | Number of bats to spawn |
| `ITERATIONS` | Integer | 50 | Number of iterations that the algorithms should run |
| `DIM` | Integer | 2 | Dimension of the problem (number of variables of the fitness function to evaluate) |
| `ALPHA` | Float | 0.8 | Alpha value to use | 
| `GAMMA` | Float | 0.895 | Gamma value to use |
| `PULSE` | Float | 0.1 | Initial pulse rate of the bats |
| `LOUDNESS` | Float | 1.0 | initial loudness of the bats |
| `FMIN` | Float | 0.0 | Minimum frequency of the bats |
| `FMAX` | Float | 1.0 | maximum frequency of the bats |
| `RADIUS` | Float | 100.0 | Spawning radius of the bats (the initial position of each bat is defined by a center `[0,...,0]` and a custom radius) |
| `FUNCTION` | `rosenbrock`/`shpere` | `shpere` | the fitness funtion to use (the options can be `rosenbrock` or `sphere`) |

There are also options relative for running the algorithm in the cluster: 
| Variable | Options |  Default | Description |
|------|---------|---------|-------------|
| `CHUNKS` | Integer | 1 | Number of chunks of the cluster to use |
| `CPUS` | Integer | 1 | Number of cpus of the cluster to use |
| `RAM`| String | `2gb` | RAM space of the cluster to use |
| `PLACE` | `pack`/`scatter` / `pack:excl` / `scatter:excl` | `pack` | displacement option for the cpus |
| `WALLTIME` | Time | `0:01:00` | The walltime for the execution |
| `QUEUE` | String | `shortCPUQ` | The PBS queue to use for scheduling the algorithm|
| `MODULE` | String | `OpenMPI/4.1.5-GCC-12.3.0` | Name of the MPI module to use |
| `MODULE_GLS` | String | `GSL/2.7-GCC-12.3.0` | Name of the GLS module to use |

For example, the following command executes the algorithm in the local machine to evaluate the 2D Rosenbrok function with 100000 bats spawned in an area specified with the center `[0,0]` and a radius of `1000` (a square with vertices `[+-1000,+-1000]`)
```
make run-local PRG=bat_algorithm_MPI PROCESSES=6 FUNCTION=rosenbrock
```
